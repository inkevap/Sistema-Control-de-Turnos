- 1. Introducción. un sistema de turnos es una herramienta clave para la gestión eficiente del tiempo y los recursos humanos en cualquier organización, ayudando a garantizar un flujo de trabajo ordenado y productivo.
- 2. Objetivo. Este caso de uso va dirigido para crear el usuario del nuevo empleado, para llevar un control de los empleados, como saber si están activos o inactivos, si están en periodo de vacaciones, licencias, permisos por el IGSS, suspensión Laboral, permiso personal entre otros.
- 3. Definición Caso de Uso 3.1. Actores


- 1. Administrador RRHH
- 2. Sistema
- 3.2. Precondiciones


- 1. Que el administrador cuente con el Rol: AdminRRHH.
- 2. Que las solicitudes enviadas por el administrador del área cuenten con el estado pendiente autorizar
- 3.3. Flujo Normal Básico


- 1. El administrador ingresa su usuario y contraseña.
- 2. El sistema valida que las credenciales sean correctas. FA01
- 3. El sistema muestra en pantalla las opciones:

- a. Mantenimiento de usuario
- b. Gestión de Roles


- 4. El usuario selecciona la opción mantenimiento de usuario. FA09
- 5. El sistema muestra en pantalla las opciones siguientes: AN03

- a. Agregar Empleado
- b. Consultar Usuario
- c. Solicitudes
- d. Botón Regresar


- 6. El administrador selecciona la opción “Agregar empleado”. FA02, FA06, FA08,
- 7. El sistema muestra en pantalla los siguientes campos: AN04


#### a. No.DPI empleado (*): (Campo de texto)

- b. Nombre Completo (*) : (Campo de texto)
- c. Usuario (*): (Campo de texto)
- d. Área (*): (Campo de texto)
- e. Turno(*):

- i. Matutino
- ii. Vespertino
- iii. Diurno


- f. Rol(*):

- i. Empleado
- ii. Admin Area
- iii. Admin RHH


- g. Supervisor (*)
- h. Correo
- i. Contraseña
- j. Botón “Registrar”
- k. Botón “Regresar”.


- 8. El administrador agrega el No.DPI del empleado
- 9. El administrador agrega el Nombre completo del empleado.
- 10. El administrador agrega el usuario para el empleado.
- 11. El administrador agrega el área del empleado
- 12. El administrador selecciona del bombo box y le asigna el turno al empleado.

- 13. El administrador selecciona del bombo box y le asigna el rol al empleado

- 14. El administrador selecciona del bombo box y le asigna el supervisor al empleado
- 15. El administrador agrega el correo del empleado.
- 16. EL administrador agrega la contraseña del usuario a crear.
- 17. El administrador selecciona el botón “Registrar”. FA08
- 18. El sistema valida que el usuario del empleado no este duplicado en base de datos. FA04
- 19. El sistema guarda en el sistema al empleado creado.
- 20. El sistema muestra en pantalla un mensaje de éxito “se creó correctamente” El sistema guarda en bitácora las acciones realizas. AN07
- 21. Fin del caso de uso.


### 3.4. Flujos Alternos

#### [FA01]: Validación de Credenciales

- 1. El sistema valida que las credencias no son correctas.
- 2. El sistema muestra un mensaje de error “Credenciales incorrectas”


- 3. El sistema retorna al paso 1 del FB.


#### [FA02]: Consultar Usuario

- 1. El administrador selecciona la opción Consultar Usuario.
- 2. El sistema muestra en pantalla un filtro de búsqueda con la lista de los empleados. AN06
- 3. El administrador busca por medio de un filtro al empleado.
- 4. El sistema muestra en pantalla los datos del empleado siendo los siguientes:


- a. Usuario
- b. Área
- c. Estado: Activo o Inactivo

- d. Acciones
- e. Botón Regresar. FA08


#### [FA03]: Estado Inactivo

- 1. El sistema valida que el usuario este activo.

- 2. El administrador selecciona la acción inactivar
- 3. El sistema muestra en pantalla un combo box con las opciones del motivo a inactivar:

- a. Permiso Personal
- b. Vacaciones
- c. Citas al IGSS
- d. Licencia de cumpleaños (1 día)
- e. Suspensión Laboral
- f. Otros


- 4. Botones:

- i. Aceptar
- ii. Cancelar


- 5. El administrador selecciona “Aceptar”. FA05
- 6. El sistema muestra en pantalla un mensaje “Se inactivo al empleado 000-000”
- 7. El sistema actualiza el estado del empleado a inactivo.
- 8. El sistema guarda en bitácora los cambios realizados.


#### [FA04]: Error al agregar empleado

- 1. El sistema valida que el empleado existe en base de datos.
- 2. El sistema muestra un mensaje en pantalla “Error: Ha ocurrido un error al registrar el empleado”
- 3. El sistema regresa al paso 6 del FB.


#### [FA05]: Botón Cancelar

- 1. El administrador selecciona la opción cancelar.
- 2. El sistema regresa al paso 3 del FA03.


#### [FA06]: Opción Solicitudes

- 1. El administrador selecciona la opción Solicitudes.
- 2. El sistema muestra en pantalla las solicitudes enviadas por el empleado, con los botones: AN05

a. Aprobar b. Rechazar c. Botón Regresar.

- 3. El administrador selecciona el botón aprobar. FA07

- 4. El sistema valida que la solicitud no haya sido aprobada previamente por otro Admin RHH . RN02

- 5. El sistema notifica la confirmación de aprobación por correo al empleado.
- 6. El usuario selecciona el botón “Regresar”
- 7. Fin del FA.


#### [FA07]: Botón Rechazar

- 1. El administrador selecciona la opción cancelar solicitud.

- 2. El sistema valida que la solicitud no haya sido aprobada previamente por otro Admin RHH . RN02

- 3. El sistema notifica por correo al empleado que su solicitud fue rechazada.
- 4. Fin del FA.


#### [FA08]: Botón Regresar

- 1. El administrador selecciona la opción regresar.
- 2. El sistema regresa a la pantalla principal.
- 3. Fin del FA.


#### [FA09]: Opción Gestión de Roles

- 1. El administrador selecciona la opción Gestión de Roles.
- 2. El sistema muestra en pantalla las opciones siguientes:

- a. Agregar Rol. i. Botón Agregar
- b. Eliminar Rol i. Botón Eliminar
- c. Botón Regresar


- 3. El administrador ingresa el usuario y el rol para el empleado.
- 4. El administrador selecciona el botón agregar.
- 5. El sistema muestra un mensaje de éxito: “La asignación de rol ha sido exitosa”
- 6. El administrador selecciona el botón regresar.
- 7. Fin del FA.


#### [FA09]: Opción Eliminar Rol

- 1. El administrador ingresa usuario y el rol a eliminar
- 2. El administrador selecciona el botón Eliminar.
- 3. El sistema muestra un mensaje de éxito: “La eliminación del rol ha sido exitosa”


- 4. El administrador selecciona el botón regresar.
- 5. Fin del FA.


#### [FA10]: Solicitud ya aprobada

- 1. El sistema valida que la solicitud ya fue aprobada previamente.
- 2. El sistema bloquea la acción de aprobación.
- 3. El sistema muestra el mensaje:
- 4. Esta solicitud ya está siendo procesada por otro administrador RHH
- 5. Fin del FA.


### 3.5. Postcondiciones

1. El sistema debe enviar un correo electrónico al empleado, notificando el motivo de su inactivación. Ver AN01

### 4. Reglas de negocio

- [RN01]: Rol administrador

1. Los cambios realizados a los empleados los modifica el administrador.

- [RN02]: Aprobación única de solicitudes


- 1. Una solicitud únicamente puede ser aprobada por un solo Admin RHH.
- 2. El sistema debe validar que una solicitud previamente aprobada o rechazada no pueda volver a ser aprobada o rechazada por otro Admin RHH.
- 3. Si la solicitud ya fue aprobada, el sistema mostrará un mensaje: “Esta solicitud ya está siendo procesada por otro administrador RHH”
